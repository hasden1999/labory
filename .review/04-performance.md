## 🔍 الملاحظات التفصيلية بالأدلة البرمجية

### [PERF-001] خوارزمية فحص تربيعية O(N×M) تعطل حلقة الأحداث (CPU Freeze on Large Databases) 🟠 عالٍ (High)
- **الموقع:** `apps/web/src/app/api/patients/route.ts:53-62`
- **المشكلة:**
  عند استرجاع قائمة المرضى، يقوم الكود بالمرور على كل مريض ثم تنفيذ مسح خطي كامل لمصفوفة العينات بالكامل دون استخدام خريطة فهرسة:
  ```typescript
  const allPatients = Array.from(patientMap.values());
  const enriched = allPatients.map((p) => {
    const patientSamples = store.samples.filter(
      (s) => s.patientId === p.id || s.patient?.id === p.id
    );
    return {
      ...p,
      samples: patientSamples,
      visitsCount: patientSamples.length,
  ```
- **الأثر:**
  إذا كان لدى المختبر 5,000 مريض و 20,000 عينة (بيانات تشغيل سنة واحدة)، فإن هذا المسار ينفذ **100,000,000 مقارنة** في الذاكرة عند كل تحديث لشاشة المرضى، مما يؤدي إلى تجميد معالج الخادم (Event Loop Blocking) وتأخر استجابة واجهة المستخدم لعدة ثوانٍ وتجاهل طلبات الفحص الواردة من الأجهزة.
- **الحل المقترح:**
  تجميع العينات مسبقاً في `Map<patientId, Sample[]>` بتعقيد $O(M)$ لمرة واحدة قبل حلقة المرضى لتصبح العملية $O(N + M)$، أو الأفضل من ذلك: استخدام استعلام Prisma المفهرس `prisma.patient.findMany({ include: { samples: true } })`.
- **الجهد:** صغير (Small).

### [PERF-002] تسلسل كامل لقاعدة البيانات JSON.stringify عند كل تعديل طفيف 🟡 متوسط (Medium)
- **الموقع:** `apps/web/src/lib/serverStore.ts:850-870`
- **المشكلة:**
  دالة `saveStoreToFile()` تقوم بتحويل كائن النظام بأكمله إلى نص وكتابته في القرص حتى عند تغيير نتيجة فحص واحد فقط:
  ```typescript
  const serialized = JSON.stringify(store, null, 2);
  fs.writeFileSync(STORE_FILE_PATH, serialized, 'utf-8');
  ```
- **الأثر:**
  مع نمو حجم ملف `lab_store.json` ليتجاوز 20 إلى 50 ميجابايت، تصبح عملية `JSON.stringify` المتكررة مستهلكة للذاكرة والمعالج، وتسبب تأخيراً ملحوظاً (I/O Bottleneck) وتآكلاً لا داعي له لقرص التخزين SSD.
- **الحل المقترح:**
  الاعتماد الحصري على SQLite كقاعدة بيانات رئيسية؛ حيث تقوم SQLite بتحديث السجلات الفردية وتفريغها عبر الـ WAL دون الحاجة لإعادة كتابة كامل قاعدة البيانات.
- **الجهد:** متوسط (Medium).

---

### [PERF-003] احتباس سجلات العينات غير المحدودة في ذاكرة RAM (Unbounded Heap Growth) 🟡 متوسط (Medium)
- **الموقع:** `apps/web/src/lib/serverStore.ts:760-770`
- **المشكلة:**
  يحتفظ المتغير العام `global.__labStore.samples` بكافة عينات وتفاصيل فحوصات المرضى السابقة في الذاكرة الحية دون أي تفريغ أو تقسيم صفحات (No Pagination in Memory).
- **الأثر:**
  ارتفاع استهلاك ذاكرة تطبيق سطح المكتب Electron بمرور الأشهر من 250 ميجابايت إلى أكثر من 1.5 جيجابايت، مما قد يتسبب في انهيار التطبيق بسبب خطأ `JavaScript heap out of memory`.
- **الحل المقترح:**
  تطبيق استراتيجية الـ Lazy Loading والتصفح المقسم (Cursor-based Pagination) عبر استعلامات Prisma واسترجاع بيانات الفترات القديمة عند الطلب فقط.
- **الجهد:** متوسط (Medium).

## ⚡ نقاط القوة في أداء النظام (Verified Strengths)
1. **فهارس Prisma الممتازة:** يحتوي ملف `schema.prisma` على فهارس مركبة ذكية تغطي أكثر الاستعلامات تكراراً مثل `@@index([isDeleted, status, isUrgent, createdAt(sort: Desc)])`.
2. **الاستفادة من نمط SQLite WAL:** تفعيل `PRAGMA journal_mode = WAL` يتيح القراءة المتزامنة دون حظر الكتابة، مما يضمن سرعة تسجيل العينات في ثوانٍ معدودة.
3. **محرك المعاينة المباشر السريع:** توليد تقارير A4 عبر SVG و HTML نظيف دون الحاجة لتشغيل محرك طباعة ثقيل في كل ثانية.
