## 🔍 الملاحظات التفصيلية بالأدلة البرمجية

### [SEC-001] تضمين المفتاح السري لتوليد وأختام التراخيص داخل الكود المصدري 🔴 حرج (Critical)
- **الموقع:** `apps/web/src/lib/licensing.ts:7`
- **المشكلة:**
  يتم تعريف المفتاح السري الرئيسي (`MASTER_SECRET`) المشترك المستخدم في توقيع التراخيص وفك تشفيرها والختم الرقمي لمكافحة التلاعب (`Tamper Seal`) بشكل نصي ثابت داخل كود الواجهة والخادم:
  ```typescript
  // Master Secret for HMAC signatures (Private to system)
  export const MASTER_SECRET = 'LAB_****'; // تم حجب باقي القيمة بموجب القاعدة الذهبية 7
  ```
- **الأثر:**
  أي شخص يقوم بفحص ملفات الـ JavaScript المترجمة في مجلد `standalone` أو استخدام أدوات استخراج النصوص من حزمة Electron يستطيع استخراج هذا المفتاح فوراً وتوليد مفاتيح ترخيص دائمة (`LIFETIME`) غير محدودة لأي جهاز دون الحاجة لشراء أو تفعيل البرنامج رسمياً.
- **الحل المقترح:**
  عزل منطق توليد التراخيص بالكامل خارج الكود المصدري للعميل (Offline Key Generator منفصل ومحمي)، واستخدام تقنية المفتاح العام/الخاص (Asymmetric Cryptography: Ed25519 أو RSA-2048) بحيث يحتوي تطبيق العميل فقط على المفتاح العام للتحقق من التوقيع (`Verify Only`) دون أن يمتلك القدرة على توقيع أي ترخيص.
- **الجهد:** متوسط (Medium).

### [SEC-002] وجود ثغرات تنفيذ أوامر عن بُعد (RCE) حرجة في حزمة Next.js على بيئة Windows 🔴 حرج (Critical)
- **الموقع:** `package.json:35` و `apps/web/package.json:14` (النسخة الحالية `next@14.2.1` / `14.2.35`)
- **المشكلة:**
  كشف فحص `npm audit` عن وجود ثغرتين برمجيتين حرجتين برقم `GHSA-p293-qw3h-jr36` (CVSS 9.0) و `GHSA-2xp9-vwfh-vxw4`:
  ```json
  "name": "next",
  "title": "Next.js: Unauthenticated Remote Code Execution on windows-hosted servers",
  "range": ">=13.4.0 <15.5.24",
  "url": "https://github.com/advisories/GHSA-p293-qw3h-jr36"
  ```
- **الأثر:**
  بما أن التطبيق يعمل على نظام Windows ويستمع على المنفذ `0.0.0.0:8080` لمشاركة الأجهزة عبر الشبكة المحلية (LAN)، فإن أي جهاز أو هاتف متصل بنفس الشبكة في المختبر يمكنه استغلال هذه الثغرة لتنفيذ أوامر برمجية خبيثة بنظام التشغيل والوصول لكامل بيانات المختبر وسيرفر ويندوز.
- **الحل المقترح:**
  تحديث حزمة `next` إلى إصدار التصحيح الآمن، أو تقييد استماع الخادم على `127.0.0.1` افتراضياً وإلزام تفعيل جدار حماية محلي على منفذ المشاركة.
- **الجهد:** صغير (Small).

### [SEC-003] استرجاع النسخ الاحتياطية ومسح البيانات دون أي مصادقة أو تحقق 🟠 عالٍ (High)
- **الموقع:** `apps/web/src/app/api/backup/restore/route.ts:6-28`
- **المشكلة:**
  نقطة النهاية الـ POST لاسترجاع النسخة الاحتياطية تستقبل البيانات وتكتبها مباشرة فوق قاعدة بيانات المختبر دون أي فحص لجلسة المستخدم (Session/Auth Token):
  ```typescript
  export async function POST(request: Request) {
    try {
      ...
      const result = restoreBackupFromFile(jsonContent);
      ...
      return NextResponse.json(result);
  ```
- **الأثر:**
  يمكن لأي متصفح أو جهاز متصل بالشبكة الداخلية للمختبر إرسال طلب استرجاع احتيالي أو تالف، مما يؤدي إلى استبدال قاعدة بيانات المرضى والتحاليل الفورية بنسخة فارغة أو خبيثة وتعطيل عمل المختبر بالكامل.
- **الحل المقترح:**
  إضافة طبقة حماية للمسار تتطلب توقيع جلسة مدير النظام (`Admin Session`) أو كلمة مرور تأكيدية قبل السماح بتمرير النسخة الاحتياطية إلى `restoreBackupFromFile`.
- **الجهد:** صغير (Small).

### [SEC-004] تجاوز مفاتيح API في استقبال نتائج الأجهزة الطبية (Device Ingest Bypass) 🟠 عالٍ (High)
- **الموقع:** `apps/web/src/lib/serverStore.ts:2026-2029` (مستدعى من `apps/web/src/app/api/devices/ingest/route.ts`)
- **المشكلة:**
  عند استقبال بيانات نتائج التحاليل الخام من أجهزة المختبر عبر بروتوكولات ASTM/HL7، إذا كان مفتاح الـ API غير صالح أو فارغ، يقوم الكود تلقائياً بالرجوع للجهاز الأول واعتماد النتائج:
  ```typescript
  // 1. Locate Device
  let device = (store.devices || []).find(d => d.id === params.deviceIdOrKey || d.apiKey === params.deviceIdOrKey);
  if (!device) {
    device = store.devices?.[0] || getInitialDevices()[0]; // ثغرة تجاوز التحقق
  }
  ```
- **الأثر:**
  إمكانية تزوير نتائج التحاليل المخبرية لعينات المرضى؛ حيث يستطيع أي جهاز غير مصرح له في شبكة المختبر إرسال نتائج تحاليل وتجاوز فحص `x-api-key` ليتم قبول النتيجة وإسنادها للمريض الأول في الطابور تلقائياً.
- **الحل المقترح:**
  رفض أي حزمة بيانات لا تحتوي على `apiKey` مسجل ومطابق بدقة، وإرجاع استجابة `401 Unauthorized`:
  ```typescript
  if (!device || !params.deviceIdOrKey || device.apiKey !== params.deviceIdOrKey) {
    return { success: false, error: 'Unauthorized device: Invalid API key' };
  }
  ```
- **الجهد:** صغير (Small).

### [SEC-005] تشغيل الروابط الخارجية في Electron دون تنقية البروتوكول (Protocol Smuggling) 🟠 عالٍ (High)
- **الموقع:** `apps/desktop/main.js:1307-1309`
- **المشكلة:**
  معالج قناة الـ IPC للروابط الخارجية يستدعي `shell.openExternal` مباشرة على الرابط الممرر من واجهة الويب دون التحقق من البروتوكول:
  ```javascript
  ipcMain.on('open-external', (event, url) => {
    shell.openExternal(url);
  });
  ```
- **الأثر:**
  إذا تم تمرير رابط يبدأ بـ `file://` أو `ms-msdt://` أو بروتوكول تنفيذي مخصص لويندوز بدلاً من `http://` أو `https://`، فقد يؤدي ذلك إلى فتح ملفات حساسة في نظام التشغيل أو تنفيذ برمجيات خبيثة محلياً.
- **الحل المقترح:**
  إلزام التحقق من البروتوكول وحصره في `http:` و `https:` فقط:
  ```javascript
  ipcMain.on('open-external', (event, url) => {
    try {
      const parsed = new URL(url);
      if (['http:', 'https:'].includes(parsed.protocol)) {
        shell.openExternal(url);
      }
    } catch {}
  });
  ```
- **الجهد:** صغير (Small).

### [SEC-006] انعدام الحماية ضد هجمات تزوير الطلبات عبر المواقع (CSRF) على نقاط API المحلية 🟡 متوسط (Medium)
- **الموقع:** `apps/web/src/app/api/` (كافة مسارات POST و PUT و DELETE)
- **المشكلة:**
  تستمع خوادم Next.js على المنفذ `8080` ولا توجد أي حماية CSRF Tokens أو التحقق من ترويسة `Origin / Sec-Fetch-Site`.
- **الأثر:**
  إذا قام فني المختبر بفتح موقع خارجي خبيث على نفس جهاز الكمبيوتر، يمكن للموقع إرسال طلبات خلفية (Fetch/XHR) إلى `http://localhost:8080/api/patients` أو حذف أو تغيير أسعار التحاليل دون علمه.
- **الحل المقترح:**
  إضافة التحقق من ترويسة `Origin` و `Host` في ملف `middleware.ts` لضمان أن كافة الطلبات تصدر حصراً من الخادم المحلي نفسه.
- **الجهد:** صغير (Small).

### [SEC-007] إمكانية استنتاج هويات المرضى عبر أرقام العينات في الرابط العام للتحقق 🟡 متوسط (Medium)
- **الموقع:** `apps/web/src/app/api/verify/[id]/route.ts:6-16`
- **المشكلة:**
  البحث عن العينة يقبل المعرف التراكمي القصير (`sampleNumber` مثل `1`, `2`, `3`):
  ```typescript
  const sample = store.samples.find((s: any) => s.id === params.id || String(s.sampleNumber) === params.id);
  ```
- **الأثر:**
  يقوم الكود بتمويه الاسم (`A. M.`)، ولكن استخدام أرقام تسلسلية يتيح للمهاجمين تجربة كافة الأرقام (Enumeration Attack) وسحب أسماء الفحوصات والتواريخ وأسماء الأطباء لكل مريض في المختبر.
- **الحل المقترح:**
  حصر استعلام التحقق بالـ `UUID` السري العشوائي فقط ومنع الاستعلام بالرقم التسلسلي البسيط (`sampleNumber`).
- **الجهد:** صغير (Small).

### [SEC-008] إفصاح رسائل الخطأ عن مسارات النظام البرمجية (Path Disclosure) 🟢 منخفض (Low)
- **الموقع:** `apps/web/src/app/api/devices/ingest/route.ts:25` و `apps/web/src/app/api/version/download/route.ts:36`
- **المشكلة:**
  إرجاع كائن الاستثناء كاملاً `error: err?.message` في استجابات الـ JSON للعميل عند حدوث خطأ 500.
- **الأثر:**
  تسريب مسارات المجلدات الداخلية (`D:\lab\...`) ومكتبات النظام.
- **الحل المقترح:**
  توحيد رسائل الأخطاء برسائل مهنية عامة وتسجيل التفاصيل في ملف السجلات الداخلي فقط.
- **الجهد:** صغير (Small).
