# تكليف وكيل التوثيق وأدلة الاستخدام (AGENT_BRIEFS/DOCS.md)

## الهدف (Goal)
تنفيذ الجزء الرابع (PART 4): كتابة توثيق هندسي شامل ومبسط بلغة عربية واضحة وموجهة لمالك المختبر غير المبرمج، إلى جانب توجيهات صارمة لأي وكيل ذكاء اصطناعي مستقبلي يعمل على هذا المستودع.

## المجلدات والملفات المملوكة (Owned Dirs & Files)
- `ARCHITECTURE.md`
- `CHANGE_GUIDE.md`
- `AGENTS.md`
- `CHANGELOG.md`
- `docs/`

## المسارات المحظورة (Forbidden Dirs)
- الكود البرمجي التنفيذي للمشروع.

## الخطوات التنفيذية (Steps)
1. كتابة `ARCHITECTURE.md` يحتوي على مخطط مبسط ورسومات توضيحية لطبقات النظام.
2. كتابة `CHANGE_GUIDE.md`: "لتغيير X، المس فقط هذه الملفات" (دليل مباشر بدون تعقيدات تقنية).
3. كتابة `AGENTS.md` في جذر المستودع بقواعد صارمة للوكلاء المستقبليين:
   - المس فقط الوحدة المحددة في الطلب.
   - لا تعدل الأجزاء الداخلية لوحدة أخرى.
   - شغّل `npm run verify` قبل إنهاء المهمة دائماً.
   - لا تجرِ تعديلات هيكلية غير مطلوبة، واعتمد التغييرات الصغيرة وتحديث `CHANGELOG`.
4. توثيق سجل التغييرات `CHANGELOG.md`.

## معايير القبول (Acceptance Criteria)
- [ ] صياغة عربية مهنية واضحة ومقروءة ومحاذاة لليمين (RTL).
- [ ] سهولة تطبيق أي تعديل لغير المبرمج بالرجوع لدليل التغيير.

## صيغة التسليم (Handoff Format)
توليد تقرير `HANDOFF_DOCS.md` يؤكد اكتمال الملفات التوثيقية الأربعة.
