# خطة إصلاح الملاحظات الثماني — Labryo LIMS

**الإصدار:** 1.0 — مسودة للاعتماد
**التاريخ:** 2026-11-03
**النطاق:** `apps/web` + `packages/data` (+ ملفات البناء المطلوبة لبند واتساب)
**حالة الكود:** لم يُعدَّل أي ملف حتى الآن. هذه الخطة مبنية على تشخيص فعلي للكود.

## 0) الملخص التنفيذي

ثماني ملاحظات، جذورها موزّعة على أربع طبقات مختلفة: (أ) مسار API غير موجود + حماية إدارية، (ب) بيانات كتالوج ناقصة، (ج) أولوية عرض خاطئة وتنسيق طباعة يقصّ النص، (د) واجهة مفقودة، (هـ) قالب طباعة واحد مكتوب يدوياً، (و) حزمة npm غير مُعلنة.

كل بند سُلِّم بمعيار واحد: **اختبار آلي يفشل قبل الإصلاح وينجح بعده**، مع دليل مرئي (لقطة شاشة أو PDF) للبنود البصرية. لا يُقبل أي بند على أساس «جرّبته واشتغل».

المجموع التقديري: **14–18 يوم-وكيل** موزّعة على 4 موجات متوازية جزئياً، بوكيل اختبار مستقل لا يكتب كود منتج.

## 3) التشخيص والإصلاح التفصيلي

### البند 1 — زر النسخ الاحتياطي

**العَرَض:** الضغط على «حفظ نسخة احتياطية الآن» يعطي رسالة خطأ دائماً.

**السبب الجذري (سببان مستقلان يجب إصلاحهما معاً):**
1. `apps/web/src/app/settings/page.tsx:612-622` → `apiRequest('/backup','POST')` أي `POST /api/backup`، والموجود فقط:
   `api/backup/snapshot`, `api/backup/list`, `api/backup/restore`, `api/backup/export` → النتيجة 404.
2. حتى لو صحّ المسار: `apps/web/src/middleware.ts:19-41` يرفض كل `/api/backup*` بـ503 إذا لم يوجد `BACKUP_ADMIN_SECRET`، و403 إذا لم تُرسل الترويسة. و`apps/web/src/lib/backupSecurity.ts:8-35` يطبّق نفس الشرط داخل كل route. الواجهة لا ترسل أي ترويسة ولا يوجد مكان يدخل فيه المستخدم المفتاح → فشل دائم على أجهزة العملاء.

**الإصلاح المقترح (بدون تعديل `.env` وبدون إضعاف الحماية):**
1. `apps/web/src/lib/backupAuth.ts` (جديد):
   - `getBackupSecret()`: يعيد `process.env.BACKUP_ADMIN_SECRET` إن وُجد، وإلا ينشئ/يقرأ `<LABRYO_DATA_DIR>/secrets/backup.key` (32 بايت hex، صلاحيات 600).
   - `createSessionToken()` / `verifySessionToken()`: HMAC-SHA256 عبر Web Crypto، الحمولة `{exp, jti}`، صلاحية 30 دقيقة.
2. `GET /api/backup/session` (جديد): يتحقق من same-origin + `Host` محلي، ثم يضبط كوكي `labryo_backup` بخاصية `HttpOnly; SameSite=Strict; Path=/api/backup`.
3. `apps/web/src/middleware.ts`: يقبل **إما** الترويسة الحالية **أو** كوكي الجلسة الموقّع. لا يُحذف شرط الترويسة (يبقى للأتمتة الخارجية). المiddleware يصبح `async` للتحقق من HMAC.
4. `POST /api/backup` (جديد): يستدعي نفس دالة `createBackupSnapshot` المستخدمة في `snapshot/route.ts` (بلا تكرار منطق)، ويعيد `{success,fileName,size,createdAt}`.
5. الواجهة: `handleCreateBackup` تستدعي `/backup/session` أولاً ثم `/backup`، وتعرض اسم الملف والحجم في رسالة النجاح.

**اختياري (يحتاج موافقة):** إضافة بطاقة «النسخ المتاحة» أسفل الزر تعرض `/api/backup/list` مع أزرار تنزيل (`export`) واستعادة (`restore`) — لأن النسخ بلا استعادة ناقص وظيفياً.

**الملفات:** `apps/web/src/app/api/backup/route.ts` (جديد)، `apps/web/src/app/api/backup/session/route.ts` (جديد)، `apps/web/src/lib/backupAuth.ts` (جديد)، `middleware.ts` 🔒، `settings/page.tsx` (منطقة SYSTEM فقط).

**معايير القبول:**
- [ ] ضغط الزر → نجاح خلال < 5 ثوان، ورسالة تحمل اسم الملف.
- [ ] ملف جديد في `backups/` بحجم > 0 وبتاريخ اليوم.
- [ ] `GET /api/backup/list` يعيد الملف الجديد.
- [ ] على جهاز بلا `BACKUP_ADMIN_SECRET` (بيئة اختبار نظيفة) يعمل الزر.
- [ ] استعادة النسخة في مجلد بيانات معزول تنجح ويعود عدد المرضى كما كان.

### البند 3 — القيم النصية لا تظهر كاملة عند الطباعة

**العَرَض:** نص المعدل الطبيعي أو النتيجة النصية يظهر ناقصاً/قديماً في الورقة المطبوعة.

**سببان مستقلان:**

**(أ) نص قديم يتغلّب على الجديد:**
- `settings/page.tsx:472-500` (`handleSaveEditTest`) يرسل `refRangeText` و`normalRange` لكنه **لا يرسل** `referenceRanges`.
- `serverStore.ts:1542` يحدّث `referenceRanges` فقط إذا أُرسلت → تبقى المصفوفة القديمة.
- `PrintBody.ts:648, 770-788` يعطي الأولوية المطلقة لـ`referenceRanges`، ولا يصل إلى `refRangeText` إلا إذا كانت فارغة (سطر 790).
→ النتيجة: المستخدم يكتب النص الجديد ويُحفظ، لكن الطباعة تعرض القديم.

**(ب) قصّ بصري للنص الطويل:**
- `PrintBody.ts:703,705,734,736` يفرض `white-space:nowrap` على كل سطر مدى مرجعي.
- `route.ts:1078` يضع `overflow:hidden` على `.report-card`.
→ أي مدى نصي طويل (مثل `Negative / Trace / 1+ / 2+ / 3+` أو وصف مزرعة) يوسّع الجدول خارج الصفحة ثم يُقصّ.

**(ج) إضافي:** النتائج متعددة الأسطر (المزارع) تُطبع بمسافات مفردة لأن `escapeHtml` لا يحوّل `\n` إلى `<br>`.

**الإصلاح:**
1. في `handleSaveEditTest`: عند تعديل النص، أرسل `referenceRanges` متزامنة:
   - إذا كان النص فارغاً → `referenceRanges: []`.
   - إذا كان هناك مدى واحد → عنصر واحد `{sex:'any', label:'', text: editRefRange}`.
   - إذا كانت هناك مديات متعددة (ذكور/إناث/أعمار) → نافذة تأكيد صريحة قبل الاستبدال، مع خيار «حدّث النص فقط واترك المديات».
2. في الطباعة: دوال موحّدة `getEffectiveRanges(test)` و`isMeaningfulRange(r)` في `print/referenceRanges.ts` (جديد) تُستخدم في كل المواضع؛ تعتبر `"Normal"` و`"-"` و`""` غير موجودة.
3. CSS: إزالة `nowrap` من خلايا المدى والنتيجة مع **الإبقاء** على `direction:ltr; unicode-bidi:isolate` (العزل هو ما يمنع انقلاب الأرقام، وليس `nowrap`)، وإضافة `overflow-wrap:anywhere; word-break:break-word; vertical-align:top`. وتغيير `.report-card` إلى `overflow:visible` داخل `@media print` فقط.
4. النتائج النصية: `white-space: pre-wrap` + تحويل `\n` إلى `<br/>` قبل `escapeHtml`.

**الملفات:** `settings/page.tsx` (CATALOG)، `PrintBody.ts` 🔒، `print/route.ts` 🔒، `print/referenceRanges.ts` (جديد).

**معايير القبول:**
- [ ] تعديل النص من الإعدادات → يظهر الجديد في المعاينة والطباعة فوراً.
- [ ] فحص بـ5 مديات نصية تُطبع كاملة بلا قصّ.
- [ ] نص مزرعة 300 حرف يُطبع كاملاً ويلتفّ داخل الصفحة.
- [ ] نتيجة متعددة الأسطر تحتفظ بأسطرها.
- [ ] لا انقلاب في الأرقام/المدى بعد إزالة `nowrap` (اختبار bidi).

**الاختبارات:** `tests/unit/print_reference_priority.test.ts` + `tests/golden/pdf_long_text_no_clip.test.ts` + فحص DOM في Puppeteer: لكل `td`، `scrollWidth <= clientWidth + 1`.

**الإصلاح (خيارَان — القرار للمستخدم):**

**الخيار أ (موصى — تعديل بناء محدود):**

**الخيار ب (عزل كامل — أثقل):** خدمة Node مستقلة داخل `apps/desktop/whatsapp-service/` بحزمها الخاصة، والويب يوكّل إليها عبر `127.0.0.1`. أكثر متانة لكنه يمسّ حزمة التثبيت وWindows Service.

**المعايير (الخيار أ):**

| `!important` متبقٍ يمنع اللون | متوسط | بند 7 لا يُغلق | اختبار بكسل يغطي 14 نمطاً × 3 ألوان |
| حزم واتساب تُنسخ ناقصة | متوسط | فشل على العميل | تشغيل الحزمة في مجلد بلا `node_modules` |
| تعارض تعديلات على `settings/page.tsx` | متوسط | كسر تبويب | مناطق محددة + مراجعة دمج orchestrator |
| حذف/إعادة تسمية بالخطأ | منخفض | فقدان | `git mv` فقط + مراجعة diff قبل الدمج |

**التراجع:** كل موجة = commit مستقل. أي فشل في بوابة → `git revert` للـcommit المحدد فقط (لا `reset --hard`). النسخ الاحتياطي مأخوذ قبل W1.
