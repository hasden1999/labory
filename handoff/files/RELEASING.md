# دليل نشر التحديثات والإصدارات الرسمية (Labryo LIMS Releasing Guide)

هذا الدليل يوضح للمطورين والمشرفين كيفية بناء وتوقيع ونشر التحديثات التلقائية لبرنامج **Labryo LIMS** بدقة وبشكل مؤتمت 100%.

---

## 🎯 دورة حياة التحديث التلقائي (How It Works)

1. **دفع الإصدار (Push Tag):** ينشئ المطور وسماً جديداً (Tag) بالصيغة القياسية `vX.Y.Z` ويدفعه إلى المستودع.
2. **البناء الآلي (GitHub Actions CI/CD):**
   - يعمل مسار العمل `.github/workflows/release.yml` على نظام Windows Server.
   - يتم تثبيت الحزم، توليد Prisma Client، بناء خادم الويب المستقل (Next.js Standalone)، وتجميع محرك Electron.
   - يتم توقيع البرنامج رقمياً (Code Signing) في حال توفر الشهادة.
   - يتم حساب تجزئات السلامة الرقمية **SHA-512** و **SHA-256** وتوليد خريطة الكتل التفاضلية (`blockmap`).
   - يُنشر Release رسمي على GitHub مع كافة ملفات التحقق.
3. **التقاط التحديث على أجهزة المستخدمين:**
   - خدمة `UpdateService` المدمجة في البرنامج تتحقق تلقائياً من وجود إصدارات جديدة كل 4 ساعات (أو يدوياً من الإعدادات).
   - يتم تحميل التحديث في الخلفية بهدوء مع شريط تقدم دون التأثير على عمل المختبر.
   - عند اكتمال التحميل ومطابقة الـ SHA-512، يظهر إشعار: *"التحديث جاهز، أعد تشغيل البرنامج لتفعيل التغييرات"*.
   - إذا اختار المستخدم **"لاحقاً"**، يُثبت التحديث تلقائياً بهدوء عند إغلاق البرنامج لاحقاً.

---

## 🚀 خطوات نشر إصدار جديد خطوة بخطوة

### الخطوة 1: تحديث رقم الإصدار في ملفات المشروع
قم بتعديل رقم الإصدار إلى الإصدار المستهدف (مثلاً `1.1.4`) في الملفات التالية:
- `apps/desktop/package.json` -> `"version": "1.1.4"`
- `apps/web/package.json` -> `"version": "1.1.4"`

### الخطوة 2: تسجيل التغييرات وعمل Commit
```bash
git add .
git commit -m "chore(release): bump version to 1.1.4"
git push origin dev
```

### الخطوة 3: إنشاء الـ Tag ورفعه
- **للإصدارات المستقرة (Stable Channel):**
  ```bash
  git tag v1.1.4
  git push origin v1.1.4
  ```
- **للإصدارات التجريبية (Beta Channel):**
  ```bash
  git tag v1.1.4-beta.1
  git push origin v1.1.4-beta.1
  ```

بمجرد رفع الـ Tag، سيبدأ الـ Pipeline على GitHub Actions فوراً وسيتولى بقية المهام تلقائياً!

## 🔐 إعدادات الأمان والتوقيع الرقمي (GitHub Secrets)

لضمان عدم ظهور تحذيرات Windows SmartScreen، يتم إعداد أسرار التوقيع في مستودع GitHub:
1. اذهب إلى: **Settings -> Secrets and variables -> Actions -> New repository secret**.
2. أضف المتغيرات التالية:
   - `CSC_LINK`: ملف الشهادة بصيغة Base64 (أو رابط لملف الشهادة PFX).
   - `CSC_KEY_PASSWORD`: كلمة مرور الشهادة الرقمية.

*(ملاحظة: إذا لم تتوفر الشهادة الرقمية، سيكتمل البناء والنشر بنجاح تلقائياً دون التوقيع، ويمكن إضافتها في أي وقت).*

## 🛡️ قواعد حماية بيئة المختبر والبيانات السريرية

1. **منع إعادة التشغيل القسرية:** لا يُجبر المستخدم إطلاقاً على إعادة التشغيل أثناء العمل على عينات أو نتائج.
2. **فحص النماذج المفتوحة:** قبل إعادة التشغيل، يتحقق النظام من عدم وجود استمارات إدخال مفتوحة أو مسودات غير محفوظة ويحذر المستخدم.
3. **النسخ الاحتياطي التلقائي قبل التحديث:** عند استدعاء التحديث، تأخذ خدمة `UpdateService` نسخة احتياطية فورية من قاعدة بيانات SQLite وملف `lab_store.json` وتخزنها في مجلد `backups` باسم `pre_update_<timestamp>`.
4. **منع الرجوع لإصدار أقدم (Downgrade Prevention):** محرك التحديث مضبوط على `allowDowngrade = false` لمنع تثبيت إصدارات أقدم قد لا تتوافق مع قاعدة البيانات.
